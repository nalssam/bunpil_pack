# 스킬 명세 (WP1)

모든 스킬은 architecture.md §3 공통 작성 규칙을 따른다. 각 항목: 목적 · 트리거 · 입력 · 출력 · 절차 요점 · 점검 · eval 3건(정상/경계/개인정보).

## bunpil-start

### setup — 설정 마법사
- 목적: 교사 맞춤 지침 파일(CLAUDE.md·AGENTS.md)과 `my-harness/` 폴더를 만든다. **첫 하네스 엔지니어링 경험.**
- 트리거: "설정 시작", "분필 설정", "처음 시작", "내 지침 만들어줘", Codex 설치 직후 onboarding.
- 인터뷰: 한 번에 한 질문, 최대 10문항, 모르면 건너뛰기 허용. ①학교급 ②학년·교과(담임/전담) ③담당 업무(부서) ④자주 만드는 문서 3가지 ⑤문체(이다체/해요체/개조식) ⑥학교 서식 특이사항 ⑦주로 쓰는 도구(한글/구글/캔바/패들렛) ⑧AI에 맡기지 않을 일 ⑨개인정보 원칙 동의 ⑩하네스 이름.
- 출력: `CLAUDE.md`와 `AGENTS.md`(동일 내용, `assets/harness-template.md` 렌더링), `my-harness/README.md`, `my-harness/rules.md`(교사가 늘려갈 규칙 목록), "첫 과제 3개" 추천.
- 채팅 전용 환경: 파일 대신 지침 전문을 보여 주고 "프로젝트 지침에 붙여 넣기"를 안내.
- eval: 초등 3학년 담임 / 질문 절반 건너뛰기 / 인터뷰 중 학생 실명 입력.

### privacy-guard — 개인정보 가드(지침)
- 목적: 훅이 없는 환경(claude.ai 채팅 등)에서도 작동하는 개인정보 원칙.
- 트리거: 학생 명단·성적·상담·설문·생활기록·사진 등 학생 자료가 언급되거나 첨부될 때, "개인정보", "가명 처리".
- 내용: 민감정보 3등급(Green 입력 가능 / Amber 주의 / Red 입력 금지, 사용자 문서 「공문 처리 Harness」 22단계 기반), 가명화 절차(학생A·B, ○학년 ○반), 파일 메타데이터(작성자) 확인, 생활기록부 서술형 금지 근거(2026 기재요령), 학습지원 소프트웨어 선정 기준상 "교사 업무용·학생 개인정보 비처리" 범위 선언.
- 출력: 가명화된 사본 제안 또는 중단 안내.

### checkup — 분필 점검
- 트리거: "분필 점검", "설치 확인", "잘 깔렸나".
- 절차: ①설치된 분필 스킬 목록 확인 ②지침 파일(CLAUDE.md/AGENTS.md) 위치·내용 요약 ③가드 테스트 안내(가짜 번호 010-0000-0000 입력 시 경고가 뜨는지) ④자동 업데이트 설정 방법 표 ⑤하네스별 안 되는 기능 안내(채팅: 훅·서브에이전트 없음).
- 출력: 상태표.

## bunpil-class (Cowork 'AI 교육자료제작 자동화' 5기능 + 루브릭)

### worksheet — 학습지
- 트리거: "학습지", "활동지", "워크시트", "문제지".
- 입력: 주제/성취기준, 학년, 수준(기본·보충·심화 3단계 선택), 문항 수, 형식(빈칸·서술·OX·연결).
- 출력: A4 인쇄용 HTML(이름·번호 칸, 머리말, 문항, 답 칸) + 별도 정답·해설 파일. 수준별 3종을 요청하면 3개 파일.
- 규칙: 정답이 학생용 파일에 섞이지 않게 분리. 성취기준 코드 표기는 확실할 때만.
- eval: 초4 과학 '물의 상태 변화' 3수준 / 주제만 있고 학년 없음 / 명렬표 첨부.

### lesson-plan — 지도안
- 트리거: "지도안", "수업 계획", "교수학습 과정안", "약안", "세안".
- 출력: 약안(1쪽 표) 또는 세안. 단계(도입·전개·정리), 교수학습 활동(교사·학생), 시간, 자료·유의점, 평가 계획. 발문 예시와 예상 반응.
- 프롬프트 체이닝: 핵심 개념 추출 → 지도안 → (요청 시) 루브릭 연결.
- eval: 중1 사회 40/45분 차시 / 차시 시간 미지정 / 학생 특이사항에 실명.

### class-slides — 수업 슬라이드
- 트리거: "수업 PPT", "교과서로 슬라이드", "수업 진행용 자료".
- 입력: 교과서 PDF·PNG(교사가 제공), 차시 목표.
- 출력: 수업 흐름 순서의 PPTX(가능 시) — 표지·학습목표·동기유발·활동·정리·형성평가. 각 슬라이드 발표자 노트에 교사 발문.
- 규칙: 교과서 이미지·본문을 통째로 옮기지 않는다(저작권). 요약·재구성하고 출처 표기. 업로드된 쪽은 교사가 수업용으로 보유한 자료임을 전제로 하되 재배포용 파일에 원본 쪽 이미지를 넣지 않는다.
- eval: 초5 국어 교과서 2쪽 / 이미지 판독 불가 / 학생 사진 포함 자료.

### papercraft — 페이퍼 크래프트
- 트리거: "페이퍼크래프트", "전개도", "접어 만들기", "입체 만들기".
- 출력: A4 SVG(실선=자르기, 점선=접기, 회색 면=풀칠) + 만드는 방법 1쪽. 기본 도형 라이브러리(정육면체·직육면체·삼각기둥·원기둥·사각뿔)로 주제 장식(라벨·간단 아이콘).
- `scripts/net.py`(표준 라이브러리만)로 전개도 좌표 생성 권장.
- eval: "태양계 행성 주사위" / 복잡한 캐릭터 요청(저작권 캐릭터 거절 후 대안) / 학생 이름 각인 요청(이름 칸만 둔다).

### coloring — 컬러링 도안
- 트리거: "색칠", "컬러링", "도안".
- 출력: A4 흑백 선화 SVG(굵은 선, 닫힌 영역, 영역 수는 학년별 조절) → PDF. 학습 연계형(낱말·번호 색칠) 옵션.
- 규칙: 저작권 캐릭터·로고 금지, 독창 도안만.
- eval: 초1 '가을 열매' / 특정 애니메이션 캐릭터 요청 / 반 학생 얼굴 사진으로 도안.

### rubric — 루브릭
- 트리거: "루브릭", "채점 기준", "평가 기준표".
- 출력: 평가요소 × 수준(3~4단계) 표, 수준별 기술은 관찰 가능한 행동으로. 성취기준 연결 열. 학생 자기평가용 쉬운 말 버전 선택.
- eval: 고1 논술형 / 평가요소만 있음 / 학생 답안 실명 포함.

## bunpil-school

### gongmun — 공문 처리 하네스 (사용자 원본 문서 기반)
- 원본: Drive 「Claude Code 교사용 공문 처리 Harness 구축 문서」. 구조·출력 형식·규칙을 그대로 따른다.

- 단계: ①문서 읽기·요약(공문별 표) ②담당자 할 일 → `outputs/memo1_todo.txt` ③교직원 안내 → `outputs/memo2_staff_message.txt` ④필요 시 HWPX/Excel 초안(자동 작성 어려우면 `*_notes.md` 항목표) ⑤검토 → `outputs/validation_report.md` ⑥`outputs/run_summary.md`.

### newsletter — 가정통신문

### pumui — 품의 도우미 (gmarket-mulpum-pumui 일반화)

- eval: 10개 품목 / 단가 누락 / 예산 초과.

### parent-survey — 학부모 설문 분석 (사용자 스킬 일반화)

- eval: 합성 응답 40건 / 열 구조 불명확 / 자유응답 속 교사·학생 실명.

### hwpx-doc — 한글 문서
- 트리거: "한글 파일로", "hwpx", "hwp로 만들어줘".

- eval: 보고서 hwpx / 플러그인 없음 / 학생 명단 포함 문서.

## bunpil-builder (하네스팀 보고서 기반)

### skill-maker — 나만의 스킬 만들기
- 트리거: "스킬 만들기", "이 일을 스킬로", "자동화 만들어줘", "반복하는 일".
- 절차: 인터뷰(무엇을·언제·입력·결과·금지) → 프롬프트 5요소(맥락·지시·입력·출력형식·제약)로 SKILL.md 초안 → 예시 1건 실행 → 교사 수정 → `my-harness/skills/<이름>/SKILL.md` 저장(원본 팩 폴더에 쓰지 않음) → 하네스별 설치 방법 안내.
- eval: "주간학습안내 만들기" / 너무 넓은 요청("학교 업무 전부") / 학생 정보 처리 스킬 요청.

### harness-fix — 실수를 규칙으로
- 트리거: "앞으로는", "다음부터", "이거 규칙으로", "또 틀렸네".
- 절차: 실수 1문장 요약 → 규칙 후보 2개 제시 → 교사 선택 → CLAUDE.md·AGENTS.md(둘 다)와 `my-harness/rules.md`에 추가 → `logs/failure-log.md` 기록(날짜·문제·원인·규칙·재시험 결과).
- eval: "학습지는 항상 2단" / 모순되는 규칙 추가 / 특정 학생 관련 규칙.

### eval-run — 내 스킬 시험하기
- 트리거: "스킬 시험", "평가해줘", "잘 되는지 확인".
- 절차: 스킬별 시험 사례(정상 3·경계 1·개인정보 1) 작성 또는 `evals/` 읽기 → 각 사례 실행 → 채점표(형식·사실성·개인정보·지침 반영) → 개선 제안.

### share-skill — 스킬 나누기
- 트리거: "스킬 공유", "동료에게 주기", "몽당분필에 올리기".
- 절차: 개인정보·학교 고유 정보 grep 점검 → README·라이선스(CC BY 4.0 권장) → zip 패키징 → 제출 안내(GitHub 이슈 템플릿 또는 이메일, 공식 편입 전 검수).

### skill-auditor (Claude 서브에이전트, model: opus, tools: Read, Grep, Glob)
- 점검: description 과잉·누락 트리거, 개인정보·외부 전송, 위험 명령(rm, curl|sh), 하네스 호환(frontmatter 키), 원본 수정 여부. 결과 보고만, 수정하지 않음.

## bunpil-connect

### connect — 커넥터 연결 도우미
- 트리거: "노션 연결", "패들렛 연결", "캔바 연결", "MCP", "커넥터".
- 절차: 지금 환경 판별 → 표면별 연결 방법(Claude Code `/mcp`, Chat·Cowork Customize→Connectors, Codex `codex mcp login <name>`) → 연결 확인 질문 1개 → 교사용 활용 예시 3개(노션 수업일지, 패들렛 게시물 정리, 캔바 디자인).
