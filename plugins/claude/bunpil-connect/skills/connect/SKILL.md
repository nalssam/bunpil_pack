# 커넥터 연결 도우미

분필 커넥터 팩은 노션(`notion`), 패들렛(`padlet`), 캔바(`canva`) 세 서비스의 원격 MCP 주소를 **등록**해 둔다. 하지만 설치만으로는 로그인되지 않는다. 교사가 쓰는 환경에서 **직접 로그인(허용)** 해야 AI가 그 서비스를 쓸 수 있다. 이 스킬은 그 과정을 한 단계씩 안내한다.

## 시작할 때

1. 작업 폴더의 `CLAUDE.md` 또는 `AGENTS.md`가 있으면 읽어 학교급·교과·문체를 반영한다. 없으면 건너뛰어도 된다(이 스킬은 연결 안내가 중심이다).
2. 어떤 서비스를 연결할지, 어떤 환경을 쓰는지 확인한다. 한 번에 한 질문만 한다.
3. 안내와 활용 예시는 모두 **초안·제안**이다. 로그인, 권한 허용, 실제 게시·수정은 교사가 직접 한다.

## 개인정보 원칙

학생 실명·학번·생년월일·주소·연락처·가족관계·사진 등 개인을 알아볼 수 있는 정보가 보이면 작업을 멈추고 '학생A'처럼 가명으로 바꾸자고 제안한다. 결과물에는 개인정보를 넣지 않는다.

커넥터는 AI가 교사의 노션 페이지, 패들렛 보드, 캔바 디자인을 **읽고 쓸 수 있게** 해 준다. 그래서 다음을 지킨다.
- 학생 실명·연락처·상담 내용·사진이 있는 페이지, 보드, 폴더는 연결 범위에서 제외하라고 권한다. 서비스에서 AI가 볼 수 있는 페이지나 보드를 고를 수 있으면 수업 자료용 공간만 고르게 한다.
- 이미 그런 정보가 든 곳을 읽으려 하면 멈추고, 교사가 가명으로 바꾼 사본을 따로 만든 뒤 그 사본으로 하자고 제안한다.
- 비밀번호, 인증 코드, 토큰을 **채팅에 입력하라고 요구하지 않고**, 교사가 보내도 받지 않는다. 로그인은 교사가 서비스의 로그인 창에서 직접 한다. AI가 대신 입력하지 않는다.

## 절차

### 1단계. 환경 확인

질문: "지금 어디에서 AI를 쓰고 계신가요? ① Claude Code(터미널·VS Code 등) ② Claude 앱 채팅·Cowork ③ Codex" 모르겠다고 하면 화면 모양을 물어 판별한다(터미널 창 → Claude Code 또는 Codex, 웹·데스크톱 앱의 채팅 → Claude 앱).

### 2단계. 환경별 연결 방법

먼저 분필 커넥터 팩(`bunpil-connect`)이 설치되어 있어야 한다. 설치가 안 되어 있으면 팩 설치부터 안내한다.

**① Claude Code**
1. 플러그인을 설치한 뒤 Claude Code를 새로 시작한다.
2. 입력창에 `/mcp`를 입력하면 연결 목록이 나온다. `notion`, `padlet`, `canva` 중 연결할 서버를 고른다.
3. 상태가 "인증 필요(needs authentication)"이면 **로그인(Authenticate)** 을 고른다. 브라우저 창이 열리면 서비스에 로그인하고 **허용**을 누른다.
4. 터미널 명령을 선호하면 `claude mcp login <이름>` 같은 방법도 있을 수 있다. 버전에 따라 다르니 [확인 필요] `/mcp` 방식이 기본이다.

**② Claude 앱 채팅·Cowork**
1. 플러그인을 설치한다(분필 커넥터 팩).
2. 사용자 지정(Customize) → 커넥터(Connectors)로 간다.
3. 목록에서 노션·패들렛·캔바 중 연결할 항목의 **연결(Connect)** 을 누르고, 열리는 로그인 창에서 직접 로그인·허용한다.
4. 연결할 서비스는 필요한 것만 켠다. 사용하지 않는 것은 꺼 둔다.

**③ Codex**
1. 플러그인을 설치한 뒤 터미널에서 `codex mcp login notion`, `codex mcp login padlet`, `codex mcp login canva` 중 필요한 것을 실행한다.
2. 브라우저가 열리면 직접 로그인·허용한다.
3. 또는 OpenAI가 공식으로 제공하는 큐레이션 플러그인(해당 서비스의 공식 항목)이 있으면 그것을 설치해 써도 된다. 이미 공식 항목을 쓰고 있다면 같은 서비스를 두 번 연결하지 않아도 된다.

서비스마다 주의:
- 노션: 로그인 뒤 AI가 접근할 수 있는 페이지·워크스페이스를 고르는 화면이 나올 수 있다. 수업용 페이지만 고른다.
- 패들렛: 교사 계정(학교 구글·MS 계정 포함)으로 로그인한다. 내 보드만 대상이다.
- 캔바: 교육용 캔바 계정으로 로그인한다. 캔바 연결 주소는 부분 확인된 상태라 연결이 안 되면 [확인 필요]로 몽당분필에 알려 달라고 한다.

### 3단계. 연결 확인 질문 1개

연결이 되었는지 아래 중 한 가지만 시켜 본다. 읽기만 하고 아무것도 만들거나 고치지 않는다.
- 노션: "내 노션에서 제목에 '수업'이 들어간 페이지 이름 3개만 알려 줘"
- 패들렛: "내 패들렛 보드 이름 목록만 보여 줘"
- 캔바: "내 캔바 디자인 제목 3개만 보여 줘"

성공하면 축하하고 활용 예시를 보여 준다. 실패하면 `references/troubleshooting.md`를 읽고 해당 증상 순서대로 한 단계씩 안내한다. 연결 확인용 결과에 학생 정보가 보이면 멈추고 그 페이지·보드는 제외하게 한다.

### 4단계. 교사용 활용 예시 (서비스별 3개)

교사가 관심 있는 서비스의 예시만 보여 주고, 해 보고 싶은 것을 고르게 한다. 쓰기·게시·삭제가 들어가는 일은 반드시 먼저 계획을 보여 주고 교사가 승인한 뒤에 한다.

**노션 — 수업일지·학급 DB**
1. 수업일지 정리: 교사가 오늘 수업 메모를 말하면 날짜·교과·단원·활동·잘된 점·고칠 점 칸으로 정리해 노션 수업일지 페이지에 새 항목으로 추가한다.
2. 학급 운영 DB 틀 만들기: 알림장, 준비물, 행사 일정을 표(데이터베이스)로 만드는 틀을 제안하고, 승인하면 새 페이지에 만든다. 학생 이름 칸 없이 번호나 '학생A' 방식만 쓴다.
3. 월말 되돌아보기: 이번 달 수업일지 페이지를 읽고 반복된 어려움과 다음 달 개선 아이디어를 한 쪽으로 요약한다.

**패들렛 — 게시물 정리·피드백 초안**
1. 게시물 정리: 수업 중 모인 패들렛 게시물을 주제별로 묶어 요약하고 비슷한 의견을 센다(작성자 이름은 빼고).
2. 피드백 초안: 게시물별로 교사가 달 댓글 초안을 쓴다. 보내기 전에 교사가 읽고 고친다. 작성자 이름은 쓰지 않고 '이 의견'처럼 쓴다.
3. 수업용 보드 준비: 토론 주제와 안내 문구가 담긴 새 보드 구성안(섹션 이름, 안내글)을 짠다. 보드 만들기는 교사가 승인한 뒤에 진행한다.

**캔바 — 디자인 초안**
1. 학급 안내 포스터 초안: 행사 이름·날짜·장소를 주면 포스터 문구와 구성안을 만들고, 캔바에서 시안을 만든다.
2. 수업 자료 표지·발표 틀: 단원 제목과 학년으로 표지와 목차 슬라이드 시안을 만든다.
3. 우리 반 규칙·급훈 카드: 문장 몇 개를 주면 교실 게시용 카드 시안을 만든다. 학생 사진과 이름은 넣지 않는다.

이 예시들은 모두 초안이며 최종 게시·출력·학부모 발송은 교사가 한다.

## 하지 않는 일

- 비밀번호·인증 코드를 대신 입력하거나 받지 않는다. 로그인 창은 교사가 직접 조작한다.
- 교사 동의 없이 노션·패들렛·캔바에 새로 만들거나 고치거나 지우지 않는다.
- 학생 정보가 있는 페이지·보드를 읽거나 요약하지 않는다.
- 학교 방화벽이나 기관 정책을 우회하는 방법을 알려 주지 않는다. 막혀 있으면 정보 담당 선생님이나 교육청 안내를 따르라고 한다.

## 점검

결과를 내기 전에 확인한다.

- [ ] 교사가 쓰는 환경을 확인했고 그 환경의 방법만 안내했다.
- [ ] 로그인과 허용을 교사가 직접 한다고 분명히 말했고, 비밀번호를 요구하지 않았다.
- [ ] 연결 확인 질문은 읽기 전용 한 가지였다.
- [ ] 학생 개인정보가 든 페이지·보드는 제외하라고 안내했다.
- [ ] 쓰기·게시가 들어가는 활용 예시는 승인 뒤에만 진행한다고 밝혔다.
