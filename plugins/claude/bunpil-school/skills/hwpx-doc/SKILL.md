# 한글(HWPX) 문서

한글 문서(.hwpx) 만들기와 내부 기안문 본문 초안 작성을 돕는다. 이 스킬은 한글 파일을 직접 쓰는 도구가 아니라 연결 안내자다. 실제 HWPX 생성은 전용 스킬·플러그인이 맡는다. 다만 "내부 기안문 본문 써줘" 요청은 이 스킬이 직접 받아 아래 '기안문 본문 초안' 절차로 쓴다.

## 시작 전

- 작업 폴더의 `CLAUDE.md` 또는 `AGENTS.md`를 읽어 학교·부서·문체를 반영한다. 없으면 문서 종류(보고서·계획서·기안문 항목)만 묻는다.
- 학교 서식 파일(hwp/hwpx)이 있으면 어떤 칸을 채울지 확인한다. 원본 서식은 고치지 않는다.

## 개인정보 원칙

학생 실명·학번·생년월일·주소·연락처·가족관계·사진 등 개인을 알아볼 수 있는 정보가 보이면 작업을 멈추고 '학생A'처럼 가명으로 바꾸자고 제안한다. 결과물에는 개인정보를 넣지 않는다.

- 학생 명단이 들어가는 문서(예: 수상자 명단, 참가자 명단)는 '학생A, 학생B'나 번호로 바꾼 뒤 작성하고, 실명 입력은 교사가 한글에서 직접 한다고 안내한다.

## 초안 규칙과 원본 보호

- 결과는 초안이다. 문서 첫머리나 파일명에 '초안'을 표시하고, 기안·결재·발송은 교사가 한다.
- 원본 hwp/hwpx 서식은 수정하지 않는다. 새 파일을 `outputs/`에 저장한다. 채팅 전용 환경이면 대화에 항목표를 제시한다.

## 절차

1. **전용 도구 확인**: 분필팩 설치 문장(teacher 묶음)은 한글 도구 세 가지를 함께 설치한다. 쓸 수 있는 도구를 확인하고 일에 맞게 고른다. 있으면 그 도구에 문서 작업을 맡기고, 이 스킬은 내용 구성과 공문서 형식 점검만 돕는다.

   | 도구 | 잘하는 일 | 확인 방법 |
   |---|---|---|
   | hwpx-plugin (airmang/hwpx-plugins) | 새 HWPX 문서 만들기·편집 | 스킬 목록에 `hwpx` |
   | kordoc (chrisryugj/kordoc) | HWP·HWPX·PDF 읽기, 두 문서 비교, 서식 빈칸 채우기, 공문 프리셋(기안문·보고서·계획서) | MCP 도구 `kordoc` |
   | hwpx_new (ZZombie04/hwpx_new) | 학교 양식(.hwpx)을 바탕으로 보고서·계획서 채우기, 미리보기 | MCP 도구 `hwpx_new` |

   기존 한글 파일을 읽거나 비교할 때는 kordoc, 받은 양식에 내용을 채울 때는 hwpx_new나 kordoc, 빈 문서를 새로 만들 때는 hwpx-plugin을 먼저 쓴다. 셋 다 없을 때만 아래 설치 안내로 간다.
2. **없으면 설치 안내**: 아래 명령을 보여 주고, 설치 여부는 사용자가 정한다. 실행은 사용자가 한다.

   Claude Code
   ```
   claude plugin marketplace add airmang/hwpx-plugins && claude plugin install hwpx-plugin@hwpx
   ```
   Codex
   ```
   codex plugin marketplace add airmang/hwpx-plugins && codex plugin add hwpx-plugin@hwpx
   ```
   Claude 앱(Chat·Cowork): 사용자 지정 → 플러그인 → 마켓플레이스 추가 → `airmang/hwpx-plugins` (Code 탭은 위의 Claude 명령을 채팅창에서 실행하게 한다)

   설치 후에는 앱을 새로 시작해야 할 수 있다(확인 필요).
3. **설치 전에도 쓸 수 있게**: 지금 바로 쓸 파일을 만든다.
   - 한글에 옮겨 적기 쉬운 **서식 항목표**(`outputs/<문서명>_서식항목표.md`): 칸 이름 → 들어갈 내용 → 근거/확인 필요 표
   - 또는 **DOCX**(만들 수 있는 환경일 때). 한글에서 열어 hwpx로 저장할 수 있다.
4. **공문서 형식 적용**: 항목 기호, 날짜·시간·금액, 붙임·끝 표시는 `references/gongmun-style.md`를 따른다. 확신이 없는 규칙은 그 문서의 '확인 필요' 표시를 그대로 둔다.
5. **자리표시자**: 서식에 `{{학교명}}`처럼 자리표시자가 분명할 때만 자동 치환을 시도하고, 모호하면 항목표로 대신한다. 서식을 덮어쓰지 않는다.

## 기안문 본문 초안 (지원하는 요청)

"내부 기안문 본문 써줘", "OO 계획 기안문 초안" 같은 요청은 이 스킬이 직접 쓴다. 한글 파일 변환은 필요할 때만 위 절차 1~3을 따른다.

1. 필요한 것만 묻는다: 제목 주제, 관련 근거(공문 번호·학교 계획·규정), 핵심 내용(일시·장소·대상·예산), 붙임 여부. 사용자가 준 사실만 쓰고, 없는 날짜·금액·번호는 지어내지 않고 '확인 필요'로 둔다.
2. 본문 순서는 다음과 같다. 항목 기호·날짜·금액 표기는 `references/gongmun-style.md`를 따른다.
   - 제목: 한 줄, 내용을 알 수 있게
   - `1. 관련:` 근거가 되는 공문·계획(없으면 이 항목을 빼고 번호를 당긴다)
   - `2.` 이후 본문: 두괄식으로 목적 → 세부 내용을 항목 기호 순서(1. → 가. → 1) → 가) → (1) → (가))로 쓴다. 항목이 하나뿐이면 기호를 붙이지 않는다.
   - 붙임: `붙임 1. ○○ 1부.` 형식으로 쓰고 마지막에 `끝.` 표시(붙임이 없으면 본문 마지막 글자 뒤에 한 칸 띄우고 `끝.`)
3. 결문(발신 명의, 기안자·검토자·결재권자, 시행 번호)은 학교 서식과 결재 체계가 다르므로 쓰지 않고, 기안·결재는 교사가 한다고 안내한다.
4. 첫머리에 '초안'을 표시하고 `outputs/<문서명>_기안문본문초안.md`로 저장한다(채팅 전용 환경이면 대화에 제시).

## 점검

- [ ] 전용 도구 유무를 확인했고, 없으면 설치 명령과 임시 산출물(DOCX 또는 항목표)을 모두 제공했는가
- [ ] 기안문 본문 초안이면 제목 → 관련 근거 → 본문 항목 → 붙임 → 끝. 순서가 맞는가
- [ ] 항목 기호 순서, 날짜(2026. 10. 13.)·시간(14:30)·금액·붙임·끝 표기가 맞는가
- [ ] 학생 이름·연락처 등 개인정보가 없는가
- [ ] 원문에 없는 내용은 '확인 필요'로 두었는가
- [ ] '초안'이 표시되었고 원본 서식이 그대로인가
