# 규칙 참고

원안: 날쌤(몽당분필) 「교사용 공문 처리 Harness 구축 문서」.

## 민감정보 등급표

| 등급 | 뜻 | 예시 |
|---|---|---|
| Green | 입력 가능 | 공개 공문, 일반 안내문, 공개 일정, 일반 서식 |
| Amber | 주의 | 가명 처리된 명단, 부서 내부 메모, 비식별 통계, 일부 예산 정보 |
| Red | 입력 금지 또는 별도 승인 | 학생 실명, 학부모 연락처, 상담 내용, 생기부 원문, 시험 원안, 징계·민원 자료, 주민등록번호·계좌번호 등 고유식별정보 |

- Green은 그대로 처리한다.
- Amber는 처리 전 사용자에게 가명·비식별 상태가 맞는지 한 번 확인한다.
- Red가 보이면 작업을 멈추고 가명 처리를 제안한다. 사용자가 학교의 별도 승인을 받았다고 밝혀도 결과물에는 옮기지 않는다.

## 사람 승인 흐름

```
AI 초안 → 담당자 1차 확인 → 개인정보 확인 → 마감·제출처 확인
→ 서식 확인 → 부장·관리자 검토 → 최종 발송·제출
```

AI는 앞의 첫 단계(초안)까지만 맡는다. 나머지는 모두 사람이 한다.

## 폴더 만들기

작업 폴더(예: `official-doc-harness/`)에 다음을 만든다. 사용자 동의를 받은 뒤 만들고, 이미 있으면 건드리지 않는다.

```
official-doc-harness/
├─ input_docs/   (공문 원본: PDF, HWPX, DOCX, XLSX, 이미지)
├─ templates/    (HWPX·Excel 서식)
├─ outputs/
└─ logs/         (failure-log.md)
```

- 처음에는 공문 2~3개만 `input_docs/`에 넣어 시험한다.
- `logs/failure-log.md`는 표 머리글만 넣어 빈 파일로 만든다(서식은 `output-formats.md`).
- 같은 폴더에 `CLAUDE.md`(또는 `AGENTS.md`)를 두면 학교급·문체가 반영된다.

## .gitignore 예시

공문과 결과물이 저장소에 올라가지 않게 한다. Git을 쓰는 경우에만 만든다.

```
input_docs/*
outputs/*
templates/private/*
logs/private/*
.env
```

## 실패 기록 방법

결과가 이상하면 `logs/failure-log.md`에 날짜 / 사용한 공문 / 발생한 문제 / 원인 / 수정한 규칙 / 재테스트 결과를 적고, 고친 규칙은 작업 폴더의 `CLAUDE.md`·`AGENTS.md`에 추가한 뒤 같은 공문으로 다시 시험한다.
