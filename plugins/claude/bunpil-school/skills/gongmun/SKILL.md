# 공문 처리 하네스

공문 파일을 폴더에 넣으면 ① 담당자 할 일 메모 ② 교직원 안내 메시지 ③ 필요 시 한글(HWPX)·엑셀 초안 ④ 검증 보고서를 만든다. AI는 초안을 만들고, 사람이 최종 책임을 진다.

원안: 날쌤(몽당분필) 「교사용 공문 처리 Harness 구축 문서」

## 시작 전

- 작업 폴더의 `CLAUDE.md` 또는 `AGENTS.md`를 먼저 읽어 학교급·담당 업무·문체를 반영한다. 없으면 꼭 필요한 것만 짧게 묻는다.
- 폴더 구조가 없으면 `references/rules.md`의 "폴더 만들기"를 보여 주고 사용자 동의 후 만든다.
- 처음에는 공문 2~3개만 넣고 시험하도록 권한다. 연습용 가상 공문은 이 스킬의 `assets/sample_input/`에 있다.

## 개인정보 원칙

학생 실명·학번·생년월일·주소·연락처·가족관계·사진 등 개인을 알아볼 수 있는 정보가 보이면 작업을 멈추고 '학생A'처럼 가명으로 바꾸자고 제안한다. 결과물에는 개인정보를 넣지 않는다.

- 민감정보 등급(Green·Amber·Red)은 `references/rules.md`를 따른다. Red 자료(학생 실명, 학부모 연락처, 상담 내용, 생기부 원문, 시험 원안, 징계·민원 자료, 주민등록번호·계좌번호 등)는 입력하지 말라고 안내한다.
- 첨부 명단 등에서 개인정보를 만나면 요약표에 '[개인정보 확인 필요]'만 표시하고 값은 옮기지 않는다.

## 초안 규칙과 원본 보호

- 모든 결과 파일 첫머리에 '초안'임을 적는다.
- 원본 공문(`input_docs/`)과 `templates/`의 서식은 절대 수정하지 않는다. 결과는 `outputs/` 아래 새 파일로 저장한다. 채팅 전용 환경이면 대화에 제시한다.
- 최종 발송·제출·결재는 사람이 한다. 메일·메신저·공문 자동 발송 기능은 쓰지 않는다.
- 생활기록부 서술형 문구 생성, NEIS·K-에듀파인 자동 입력은 하지 않는다.

## 기본 규칙

1. 공문에 없는 내용은 임의로 만들지 않는다.
2. 날짜·기관명·제출처·마감일은 반드시 원문 근거를 확인한다.
3. 불확실한 내용은 '확인 필요'로 표시한다.
4. 공문에 적힌 역할(예: 안전교육 담당 교사)은 그대로 쓰고, 사람 이름은 지정하지 않는다. 담당자 개인이 불명확하면 '담당자 확인 필요'로 적고, 역할이 있으면 괄호로 덧붙인다.
5. 마감이 없으면 기한을 추측하지 않고 '확인 필요'.
6. 학생 실명·주민번호·연락처·상담 내용은 결과물에 노출하지 않는다.
7. HWPX·엑셀은 초안으로만 만든다.

## 절차 (6단계)

서브에이전트를 쓸 수 있는 환경이면 document-reader → task-extractor → message-writer → draft-generator → risk-reviewer 순서로 맡기고, 없으면 같은 단계를 직접 순서대로 수행한다.

1. **문서 읽기·요약** (document-reader): `input_docs/`의 파일을 모두 읽고 공문별 요약표를 만든다. 항목은 파일명·제목·발신 기관·수신 대상·시행일·마감일·할 일·교직원 전달 내용·첨부 여부·확인 필요. 읽을 수 없는 형식(스캔 이미지 등)은 읽지 못했다고 밝히고 사용자에게 알린다.
2. **담당자 할 일** (task-extractor): 공문별로 구분해 `outputs/memo1_todo.txt` 작성.
3. **교직원 안내** (message-writer): 짧고 명확하게, 요청·기한·제출 방법을 포함해 `outputs/memo2_staff_message.txt` 작성.
4. **초안 생성** (draft-generator): 사용자가 한글·엑셀 초안을 요청했거나 `templates/`에 서식이 있을 때만 수행한다. 요청이 없고 `templates/` 서식도 없으면 4단계는 건너뛰고 `run_summary.md`에 '초안 파일: 해당 없음(요청·서식 없음)'으로 적는다. 수행할 때는 `templates/`를 참고해 `outputs/`에 새 파일을 만든다. HWPX는 자리표시자(`{{학교명}}` 등)가 명확할 때만 자동 치환하고, 어려우면 `draft_report_notes.md` 항목표로 대신한다. 엑셀은 머리글·셀 기준이 분명할 때만 채우고, 아니면 `draft_table_notes.md`. 한글 파일 생성은 `hwpx-doc` 스킬을 참고한다.
5. **검토** (risk-reviewer): 근거 없는 내용, 날짜·마감·제출처 정확성, 담당자 임의 지정, 개인정보 노출, 빈칸, 사람 확인 표시를 점검해 `outputs/validation_report.md` 작성.
6. **실행 요약**: `outputs/run_summary.md`에 처리한 공문 목록, 만든 파일, 확인 필요 사항 수, 다음 행동을 정리한다. 문제가 있었으면 `logs/failure-log.md`(날짜/사용한 공문/문제/원인/수정한 규칙/재테스트 결과)에 기록하도록 권한다.

출력 파일의 고정 서식은 `references/output-formats.md`를 그대로 따른다.

## 사람 승인 흐름

AI 초안 → 담당자 1차 확인 → 개인정보 확인 → 마감·제출처 확인 → 서식 확인 → 부장·관리자 검토 → 최종 발송·제출. 마지막 보고에 이 흐름을 한 줄로 상기시킨다.

## 금지

근거 없는 지시사항 생성, 담당자 사람 이름 임의 지정, 제출 기한 추측, 학생 개인정보 복사, 원본 서식 덮어쓰기, 사람 승인 없는 발송.

## 점검

결과를 내기 전에 확인한다.

- [ ] 모든 날짜·기관·마감·제출처를 원문에서 다시 찾았는가
- [ ] 원문에 없는 내용을 넣지 않았고, 불확실한 곳에 '확인 필요'를 달았는가
- [ ] 공문에 적힌 역할은 그대로 쓰고 사람 이름은 정하지 않았는가
- [ ] 결과물에 학생 실명·연락처 등이 없는가
- [ ] 모든 파일이 '초안'으로 표시되고 `input_docs/`가 그대로인가
- [ ] 고정 서식(`references/output-formats.md`)과 파일명이 맞는가
