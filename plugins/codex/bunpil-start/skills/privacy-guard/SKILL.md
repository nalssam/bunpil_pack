# 개인정보 가드

선생님의 AI 작업에서 학생 개인정보가 새어 나가지 않도록 하는 원칙이다. 자동 점검(훅)이 없는 환경에서도 이 지침이 먼저 작동한다.

개인정보 원칙: 학생 실명·학번·생년월일·주소·연락처·가족관계·사진 등 개인을 알아볼 수 있는 정보가 보이면 작업을 멈추고 '학생A'처럼 가명으로 바꾸자고 제안한다. 결과물에는 개인정보를 넣지 않는다.

## 1. 등급 판단 (먼저 한다)

| 등급 | 예 | 처리 |
|---|---|---|
| Green 사용 가능 | 공개 공문, 일반 안내문, 공개 일정, 빈 서식 | 그대로 진행 |
| Amber 주의 | 가명 처리된 명단, 부서 내부 메모, 비식별 통계, 일부 예산 정보 | 필요한 부분만 쓰고 결과물에 원문 복사 금지 |
| Red 입력 금지 | 학생 실명, 학부모 연락처, 상담 내용, 생기부 원문, 시험 원안, 징계·민원 자료, 주민등록번호·계좌번호 | 작업 중단 → 가명 처리 제안 |

출처: 날쌤(몽당분필) 「교사용 공문 처리 Harness」 민감정보 등급표.

## 2. Red·Amber 자료를 받았을 때

1. 작업을 멈추고 무엇이 개인정보인지 열 이름이나 항목명만 알려 준다. 개인정보 내용을 다시 옮겨 적지 않는다.
2. 선택지를 준다.
   - (가) 선생님이 가명 처리한 파일을 다시 올린다.
   - (나) AI가 가명 사본을 만든다: 이름 → 학생A·B·C, 반·번호 → ○학년 ○반, 연락처·주소·생년월일 열 삭제. 원본은 수정하지 않고 `outputs/익명화_사본.*`로 저장한다. 대응표(실명↔가명)는 만들지 않는다.
   - (다) 개인정보 열을 빼고 필요한 열만 쓴다.
3. 선택 후 진행하고, 결과물 끝에 "익명화 처리 내역" 한 줄을 남긴다(예: "이름 1열·연락처 1열 삭제, 자유응답 속 실명 3건 치환").

## 3. 파일 메타데이터

문서 파일의 작성자·수정자 정보에 교사 실명이 들어갈 수 있다. 공유용 결과물을 만들 때는 작성자 속성을 비우거나 "작성자" 정도로 둔다고 안내한다.

## 4. 하지 않는 일

- 생활기록부 서술형 항목 문구를 생성해 그대로 쓰게 하는 일. 「2026학년도 학교생활기록부 기재요령」은 AI 생성 자료를 서술형 항목에 그대로 입력하는 행위를 금지한다. 교사가 쓴 글의 맞춤법 확인 같은 보조는 최종 확인을 전제로만 돕는다.
- 학생이 직접 이 도구를 쓰게 하는 일. 분필팩은 교사가 수업 준비·행정 업무에 쓰는 도구이며 학생 개인정보를 처리하지 않는 것을 전제로 한다.
- 개인정보가 담긴 파일을 외부 서비스(커넥터)로 보내는 일.

## 5. 자동 점검(훅)과의 관계

Claude Code·Cowork·Codex(훅 신뢰 후)에서는 분필 시작 팩의 훅이 입력과 파일 쓰기를 점검한다. 웹 채팅에는 훅이 없으므로 이 지침이 유일한 가드다.

| 패턴 | 동작 |
|---|---|
| 주민·외국인등록번호 하이픈 형식(6자리-7자리) | 입력 차단, 파일 쓰기 시 확인 요청 |
| 하이픈 없는 13자리 숫자 | 경고(바코드·주문번호일 수 있음) |
| 휴대전화 번호 | 경고 |
| "N학년 N반 N번" | 경고 |

한계: 공백·전각 숫자·줄바꿈으로 나뉜 번호, 이름만 있는 명단, 사진은 잡지 못한다. 그래서 위 1~2절의 판단은 AI와 선생님이 직접 한다. 더 자세한 기준은 `references/policy.md`를 본다.

모든 결과는 초안이며 최종 판단은 선생님이 한다.

## 점검

- [ ] 결과물에 실명·연락처·학번·생년월일이 없는가
- [ ] 익명화 처리 내역을 남겼는가
- [ ] 원본 파일을 수정하지 않았는가
- [ ] 가명 대응표를 만들지 않았는가
