# 출력 파일 고정 서식

원안: 날쌤(몽당분필) 「교사용 공문 처리 Harness 구축 문서」. 파일명과 항목 순서를 바꾸지 않는다. 모든 파일의 맨 첫 줄에 `※ 초안 — 사람 확인 전 사용 금지`를 한 줄 넣고, 제목(`# …`)은 그 다음 줄에 둔다.

## 출력 파일 목록

| 파일 | 내용 |
|---|---|
| `outputs/memo1_todo.txt` | 담당자 할 일 메모 |
| `outputs/memo2_staff_message.txt` | 교직원 안내 메시지 초안 |
| `outputs/draft_report.hwpx` 또는 `outputs/draft_report_notes.md` | 한글 보고서·계획서 초안(자동 작성이 어려우면 항목표). 요청·서식이 모두 없으면 만들지 않는다 |
| `outputs/draft_table.xlsx` 또는 `outputs/draft_table_notes.md` | 엑셀 표 초안(불명확하면 항목표). 요청·서식이 모두 없으면 만들지 않는다 |
| `outputs/validation_report.md` | 검증 보고서 |
| `outputs/run_summary.md` | 실행 요약 |

## memo1_todo.txt

공문이 여러 건이면 아래 블록을 공문마다 반복하고 구분선(`----`)을 둔다.

```
※ 초안 — 사람 확인 전 사용 금지
[담당자 할 일 메모]

1. 공문 제목:
2. 담당자:
3. 해야 할 일:
4. 마감일:
5. 제출처:
6. 필요한 첨부파일:
7. 확인 필요 사항:
8. 우선순위:
```

- 마감이 없으면 `4. 마감일: 확인 필요 (공문에 기재 없음)`.
- 공문에 적힌 역할은 그대로 쓰고 사람 이름은 지정하지 않는다. 개인이 불명확하면 `2. 담당자: 담당자 확인 필요 (공문상 역할: 학교별 안전교육 담당 교사)`처럼 역할이 있으면 덧붙이고, 없으면 `2. 담당자: 담당자 확인 필요`.
- 우선순위는 마감 임박도와 공문의 요구 강도로 상·중·하로 쓰되 근거를 한 줄 덧붙인다.

## memo2_staff_message.txt

```
※ 초안 — 사람 확인 전 사용 금지
[교직원 안내 메시지 초안]

선생님들께 안내드립니다.

1. 관련 공문:
2. 요청 사항:
3. 제출 또는 회신 기한:
4. 제출 방법:
5. 유의사항:

감사합니다.
```

- 짧고 명확하게 쓴다. 공문에 없는 내용은 쓰지 않는다.
- 기한·제출 방법이 공문에 없으면 `확인 필요`로 둔다.

## validation_report.md

```
※ 초안 — 사람 확인 전 사용 금지
# 검증 보고서

## 1. 전체 판단 (사용 가능 / 수정 필요 / 사용 보류)
## 2. 발견된 문제
## 3. 확인 필요 사항
## 4. 개인정보·민감정보 위험
## 5. 최종 사용 전 사람 검토 항목
```

- 1번은 세 가지 중 하나만 고르고 한 줄 이유를 붙인다.
- 2번은 `파일명 / 항목 / 문제 / 원문 근거` 표로 쓴다.
- 5번에는 사람 승인 흐름(담당자 1차 확인 → 개인정보 확인 → 마감·제출처 확인 → 서식 확인 → 부장·관리자 검토 → 최종 발송·제출)을 체크박스로 넣는다.

## run_summary.md

```
※ 초안 — 사람 확인 전 사용 금지
# 실행 요약

- 실행일:
- 처리한 공문: (파일명 목록)
- 만든 파일: (목록)
- 초안 파일: (만들었으면 파일명, 요청·서식이 없어 건너뛰었으면 '해당 없음(요청·서식 없음)')
- 확인 필요 사항: n건
- 전체 판단: (validation_report 1번 결과)
- 다음 행동: (사람이 할 일 3개 이내)
```
