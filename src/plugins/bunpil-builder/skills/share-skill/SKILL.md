# 스킬 나누기

내가 만든 스킬을 동료에게 주거나 몽당분필에 제안하기 전에, **학생·학교 정보가 새어 나가지 않게 점검**하고 받는 사람이 바로 쓸 수 있게 포장한다. 나눔은 교사가 결정한다. 이 스킬은 메일 발송, 업로드, 이슈 등록을 대신하지 않는다.

## 시작할 때

1. 작업 폴더의 `CLAUDE.md` 또는 `AGENTS.md`를 읽어 문체와 학교급을 파악한다. 없으면 필요한 것만 짧게 묻는다.
2. 나눌 스킬 폴더를 정한다. 보통 `my-harness/skills/<이름>/`이다. 설치된 분필팩 스킬은 이미 공개된 것이므로 대상이 아니다.
3. **원본은 고치지 않는다.** 점검과 정리는 `outputs/share/<이름>/` 아래 복사본에서 한다. 원본에는 어떤 파일도 쓰지 않는다.
4. 모든 결과는 초안이며 공유 여부와 제출은 교사가 정한다.

## 개인정보 원칙

학생 실명·학번·생년월일·주소·연락처·가족관계·사진 등 개인을 알아볼 수 있는 정보가 보이면 작업을 멈추고 '학생A'처럼 가명으로 바꾸자고 제안한다. 결과물에는 개인정보를 넣지 않는다.

점검 결과를 보고할 때도 찾은 개인정보 원문을 그대로 옮겨 적지 않는다. 파일 이름·줄 번호와 종류("휴대폰 번호 1건")만 말하고, 내용 일부는 `010-****-****`처럼 가린다.

## 절차

### 1단계. 파일 목록 확인

복사본 폴더의 모든 파일을 나열한다. 허용되는 구성은 아래뿐이다.
```
<이름>/
├── SKILL.md
├── README.md        (이 스킬이 추가)
├── LICENSE          (이 스킬이 추가)
├── references/      (선택)
├── assets/          (선택)
└── scripts/         (선택, 있으면 내용을 교사에게 설명)
```
다음이 보이면 제외하자고 제안한다: 학생 명단·성적표·스캔 파일, 실제 공문, 사진, `.env`, 열쇠·토큰 파일, `.bak`, 업무 `outputs/`, 압축 파일.

### 2단계. 개인정보·학교 고유 정보 점검

복사본 폴더 전체(하위 폴더 포함)에서 아래 패턴을 하나씩 검색한다. 명령을 실행할 수 있으면 `grep -rnE '<패턴>' <폴더>` 형태로 돌리고(`|`는 "또는"), 실행할 수 없으면 파일을 읽으며 같은 종류를 직접 찾는다.

```
# 1 주민등록번호 (발견 즉시 삭제)
[0-9]{6}-?[1-4][0-9]{6}
# 2 휴대폰 (삭제 또는 010-0000-0000)
01[016789]-?[0-9]{3,4}-?[0-9]{4}
# 3 일반 전화 (삭제)
0[2-6][0-9]?-[0-9]{3,4}-[0-9]{4}
# 4 이메일 (삭제 또는 example@example.com)
[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}
# 5 학교 이름 (○○초등학교로 치환)
[가-힣]+(초등학교|중학교|고등학교)
# 6 학년 반 (○학년 ○반으로 치환)
[0-9]학년 ?[0-9]+반
# 7 학년 반 번호 (삭제)
[0-9]학년 ?[0-9]+반 ?[0-9]+번
# 8 주소 (삭제 또는 ○○시 ○○로)
[가-힣]+(시|군|구) [가-힣0-9]+(로|길|동) ?[0-9-]*
# 9 키·토큰 (삭제하고 해당 키는 즉시 폐기)
(sk-|ghp_|xox[bp]-|AKIA)[A-Za-z0-9_-]{10,}
# 10 비밀번호 표기 (값 삭제)
(비밀번호|패스워드|password|passwd)[[:space:]]*[:=]
# 11 개인 컴퓨터 경로 (~/ 로 치환)
/(Users|home)/[^/ ]+/
```

패턴 1~5는 반드시 돌린다. 5번은 "초등학교 3학년용"처럼 학교 이름이 아닌 일반 표현은 잡지 않는다. 걸린 것이 실제 학교 이름인 경우만 고친다.

보조 점검(패턴으로 못 잡는 것은 눈으로 읽는다).
- 학생·교사 **이름**: 예시 문장에 실명이 있는가. 있으면 '학생A', '○○ 선생님'으로 바꾼다.
- 학교 고유 약어, 교장·교감 이름, 학교 홈페이지 주소, 내부 폴더 이름.
- 특정 학급 일정·행사처럼 학교를 알아볼 수 있는 구체 사례.
- 실제 공문 문구를 그대로 붙여 넣은 부분(저작권·보안). 일반화해서 다시 쓴다.

결과는 표로 보고한다: `파일 | 줄 | 종류 | 조치 제안`. 하나도 없으면 "패턴 점검에서 발견된 것 없음. 눈으로 읽은 범위: …"라고 쓴다. 패턴 점검은 완벽하지 않으니 교사가 마지막으로 한 번 훑어보게 한다.

교사가 동의한 조치만 복사본에 반영하고 다시 검색해 0건을 확인한다.

### 3단계. 스킬 자체 점검

- frontmatter가 `name`, `description`만이며 `name`이 폴더 이름과 같은가.
- 이름이 ASCII 소문자·숫자·하이픈이고 `claude`·`anthropic`으로 시작하지 않는가.
- `description`이 600자 이내이고, 트리거가 앞에 있으며 쓰지 않을 때가 적혀 있는가.
- `rm -rf`, `curl … | sh`, 비밀번호 입력 대행, 외부 서버로 자료 전송 같은 위험 명령이 없는가. 스크립트가 있다면 무엇을 하는지 교사에게 설명했는가.
- 설치된 팩 폴더에 쓰는 지시가 없는가.
- 개인정보 원칙 블록과 "초안" 문장이 있는가.

Claude Code를 쓴다면 `skill-auditor` 서브에이전트에게 복사본 폴더를 읽고 보고만 하게 시킬 수 있다고 안내한다. 사용할 수 없으면 위 항목을 직접 점검한다.

### 4단계. README.md 만들기

복사본 폴더에 `README.md`를 쓴다.

```
# <스킬 표시 이름> (<이름>)

한 줄 설명:
이런 때 쓴다: (트리거 말 3~5개)
이런 때는 쓰지 않는다:

## 설치
- Claude 앱: 사용자 지정 → 스킬 → 업로드로 zip을 올린다
- Claude Code: ~/.claude/skills/<이름>/ 또는 프로젝트 .claude/skills/<이름>/
- Codex: ~/.agents/skills/<이름>/ 또는 저장소 .agents/skills/<이름>/

## 사용 예
(입력 예 → 출력 예. 가상 자료만)

## 주의
- 결과는 초안이며 최종 제출·발송은 교사가 한다.
- 학생 개인정보는 가명으로 바꿔서 쓴다.

## 만든 이 · 날짜 · 버전
(교사가 공개하고 싶은 이름이나 별칭만. 학교 이름은 쓰지 않는다)

## 라이선스
CC BY 4.0 (LICENSE 참고)
```
만든 이 표기에 실명·학교를 쓸지는 교사에게 묻고, 기본은 별칭 또는 비워 두기이다.

### 5단계. 라이선스

- 권장: **CC BY 4.0**(출처만 밝히면 누구나 쓰고 고칠 수 있음). `LICENSE`에 `이 스킬은 CC BY 4.0 라이선스로 공개합니다. https://creativecommons.org/licenses/by/4.0/deed.ko` 와 저작자 표기를 쓴다. 전문(legalcode)은 위 주소에서 받아 붙이도록 안내한다. AI가 법적 문구를 새로 만들지 않는다.
- 다른 선택(MIT, CC0, 비공개 공유)도 설명하되 고르는 것은 교사이다.
- 스킬 안에 다른 사람의 저작물(교과서 본문, 상업 이미지, 유료 템플릿)이 있으면 라이선스를 붙일 수 없으니 빼도록 한다.
- 소속 학교·기관의 업무 규정상 외부 공개가 가능한지 교사가 확인하게 한다.

### 6단계. zip 패키징

zip 안의 구조는 **스킬 폴더가 최상위**여야 한다.
```
weekly-notice.zip
└── weekly-notice/
    ├── SKILL.md
    ├── README.md
    ├── LICENSE
    └── references/ ...
```
- 파일을 실행할 수 있으면 `outputs/share/` 에서 `zip -r weekly-notice.zip weekly-notice` (Windows는 폴더를 마우스 오른쪽 → 압축). 폴더 안이 아니라 **폴더째** 묶는다.
- 만든 뒤 zip 안 목록을 확인해 `SKILL.md`가 `<이름>/SKILL.md`에 있는지, 제외하기로 한 파일이 없는지 본다.
- 숨은 파일(`.DS_Store`, `.git`)은 넣지 않는다.
- 실행할 수 없는 환경이면 구조와 명령을 안내하고 교사가 직접 묶게 한다.

### 7단계. 제출 안내

몽당분필에 제안하려는 경우에만 안내한다. **자동으로 전송하지 않는다.**

1. **GitHub 이슈**: 분필팩 저장소의 새 이슈에서 "스킬 제안" 템플릿을 고르고, 스킬 이름·한 줄 설명·트리거 말·쓰는 상황·개인정보 점검 완료 체크·zip 첨부를 적는다. (저장소 주소와 템플릿 이름은 정식 공개 시점에 몽당분필 안내를 따른다. [확인 필요])
2. **이메일**: `bunpil@mdbf.co.kr` (**[확인 필요]** 실제 접수 주소인지 몽당분필 공지에서 확인한 뒤 보낼 것). 제목은 `[스킬 제안] <스킬 이름>`, 본문에 위 항목, zip 첨부.
3. 공식 팩에 편입되기 전에 몽당분필의 검수(개인정보, 저작권, 호환성, 시험 결과)를 거친다는 점, 채택 여부와 수정 요청이 있을 수 있다는 점을 알린다.
4. 동료에게 직접 줄 때는 zip과 README를 주고, 받는 사람이 `skill-auditor`나 눈으로 `SKILL.md`를 읽어 본 뒤 설치하라고 권한다.

제안문 초안(이메일·이슈 본문)을 써 줄 수 있다. 보내기는 교사가 직접 한다.

## 하지 않는 일

- 교사 동의 없이 파일을 보내거나 올리지 않는다.
- 원본 스킬 폴더나 설치된 팩 폴더를 고치지 않는다.
- 점검에서 나온 개인정보 원문을 채팅이나 보고서에 그대로 옮기지 않는다.

## 점검

결과를 내기 전에 확인한다.

- [ ] 복사본 폴더에서 점검했고 원본은 그대로이다.
- [ ] 위 패턴(주민번호·휴대폰·이메일·학교명·학년 반)이 0건이고, 눈으로 읽어 실명도 없다.
- [ ] frontmatter가 `name`·`description`뿐이고 위험 명령이 없다.
- [ ] README와 LICENSE가 있고, 제외 대상 파일이 빠졌다.
- [ ] zip 안에서 `<이름>/SKILL.md` 구조가 확인된다.
- [ ] 제출 주소가 `[확인 필요]`로 표시되어 있고, 보내기는 교사가 직접 한다고 안내했다.
