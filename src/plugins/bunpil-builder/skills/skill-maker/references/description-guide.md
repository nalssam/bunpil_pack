# description 잘 쓰는 법

`description`은 AI가 "지금 이 스킬을 켤까?"를 정하는 유일한 단서이다. 본문은 스킬이 켜진 뒤에야 읽힌다. 그래서 description이 부실하면 스킬이 안 켜지거나(과소 작동), 엉뚱할 때 켜진다(과잉 작동).

## 1. 기본 구조 (600자 이내)

```
[트리거 말 3~6개], [비슷한 표현] 같은 요청에 쓴다. [무엇을 해 주는지 한 문장].
[쓰지 않을 때 1~2개]에는 쓰지 않는다.
```

- **트리거 말은 앞에 둔다.** 교사가 실제로 입력할 말투 그대로 적는다("학습지 만들어줘", "활동지", "워크시트").
- **동의어를 넣는다.** 같은 일을 부르는 이름이 여럿이다(지도안·약안·세안·교수학습과정안).
- **쓰지 않을 때를 적는다.** 비슷한 스킬과 겹치지 않게 한다.
- **한 스킬은 한 가지 일.** description에 "그리고"가 세 번 넘게 나오면 스킬을 쪼갠다.
- 600자를 넘기지 않는다. 길면 뒤쪽이 잘릴 수 있다.
- 따옴표로 시작하지 않는다. 콜론(`: `)과 ` #`은 피한다(frontmatter 해석 오류 방지).
- 학교 이름, 교사 이름, 학생 이름은 넣지 않는다.

## 2. 좋은 예 / 나쁜 예

### 예 1. 주간학습안내

나쁜 예 (너무 막연하다 — 안 켜진다)
```
description: 학교 안내문을 만드는 스킬이다.
```
문제: 교사가 "주간학습안내 만들어줘"라고 해도 "학교 안내문"과 연결되지 않을 수 있다. 무엇을 입력받고 무엇을 내는지 없다.

좋은 예
```
description: 주간학습안내, 주간 안내, 이번 주 학습 안내, 다음 주 안내문 같은 요청에 쓴다. 교과별 학습 내용과 준비물을 받아 학부모용 A4 한 쪽 안내 초안을 만든다. 가정통신문 전체나 공문, 알림장 한 줄 작성에는 쓰지 않는다.
```

### 예 2. 과잉 작동

나쁜 예 (아무 때나 켜진다)
```
description: 글쓰기, 문서, 표, 안내, 자료, 정리, 작성, 요약 등 모든 문서 작업에 쓴다.
```
문제: 거의 모든 요청에 켜져 다른 스킬을 가린다. 교사가 원하지 않은 서식이 끼어든다.

좋은 예
```
description: 회의록 정리, 협의회록, 부서 회의 기록 같은 요청에 쓴다. 회의 메모를 안건·결정·할 일 표로 정리한다. 공문 요약이나 가정통신문 작성에는 쓰지 않는다.
```

### 예 3. 트리거가 뒤에 숨은 경우

나쁜 예
```
description: 이 스킬은 교사의 업무 부담을 줄이고 효율을 높이기 위해 만들어졌으며, 다양한 상황에서 활용할 수 있다. 수행평가 루브릭을 만들 때 쓴다.
```
문제: 앞 70자가 쓸모없는 설명이다. 핵심 말이 맨 뒤에 있다.

좋은 예
```
description: 루브릭, 채점 기준, 평가 기준표, 수행평가 기준 같은 요청에 쓴다. 평가 요소와 3단계 수준을 관찰 가능한 행동으로 적은 표 초안을 만든다. 생활기록부 문구 작성에는 쓰지 않는다.
```

### 예 4. 개인정보를 끌어들이는 경우

나쁜 예
```
description: 김OO 학생 상담 기록을 정리한다. ○○초 3학년 2반 전용.
```
문제: 특정 학생 이름과 학교 이름이 들어 있다. 공유하면 안 된다.

좋은 예
```
description: 상담 일지 정리, 상담 기록 요약 같은 요청에 쓴다. 교사가 가명(학생A)으로 바꾼 상담 메모를 날짜·주제·후속 조치 표로 정리한다. 실명이 들어 있으면 가명 처리부터 제안한다. 생활기록부 문구 작성에는 쓰지 않는다.
```

### 예 5. 지침 대신 스킬을 만든 경우

"항상 존댓말로 써라" 같은 한 줄 규칙은 스킬이 아니라 `CLAUDE.md`/`AGENTS.md`의 규칙이다(`harness-fix` 사용). 스킬은 **절차가 있는 반복 업무**일 때 만든다.

## 3. 쓴 뒤 시험하기

1. 트리거 말 5개를 다른 표현으로 입력해 본다. (예: "주간학습안내 만들어줘", "다음 주 안내문 써줘", "이번 주 학습 내용 학부모한테 보낼 거야")
2. 켜지면 안 되는 말 3개를 입력해 본다. (예: "가정통신문 써줘", "공문 요약해줘")
3. 켜지지 않은 말의 표현을 description 앞쪽에 추가한다. 엉뚱하게 켜진 말은 "쓰지 않는다" 문장에 추가한다.
4. `eval-run`으로 정리해 두면 고칠 때마다 다시 시험할 수 있다.

## 4. 점검표

- [ ] 트리거 말이 첫 문장에 있다
- [ ] 동의어 3개 이상
- [ ] 무엇을 입력받아 무엇을 내는지 한 문장
- [ ] 쓰지 않을 때를 적었다
- [ ] 600자 이내, 이름·학교명 없음
